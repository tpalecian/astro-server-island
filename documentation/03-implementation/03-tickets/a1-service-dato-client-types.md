# Ticket A1 — service-dato client + base types

---

## Description, Value & ACs

**Scope (simple terms):**  
Implement the Dato client wrapper and base CMS-agnostic types in `packages/service-dato`. This establishes the data-access layer so all downstream CMS work (GQL, getters, app) can run without app coupling.

**What we're trying to achieve / outcome we expect:**  
Client setup and core types in place. The app will never import the client directly; getters exported from the CMS package will use it. Query result types come from GraphQL codegen in `types-dato.ts`; base types in `types.ts` stay CMS-agnostic.

**Value (user / client's business):**  
Enables all downstream CMS work without app coupling. Single place for Dato config and token; type-safe foundation for getters.

**Acceptance criteria:**

| #   | Criterion                                       | Done |
| --- | ----------------------------------------------- | ---- |
| AC1 | Client wrapper exists and reads token from env. |      |
| AC2 | Base types compile and are exported internally. |      |

## Feasibility & Dependencies

**Blocking:** None.  
**Unblocks:** GQL fragments + codegen; getters + exports (and models if any).

**Dependencies / risks:**  
None. Requires `DATOCMS_API_KEY` (or equivalent) in env for getter token when exercising the client.
